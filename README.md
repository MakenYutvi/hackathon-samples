# AI Hackathon — demo samples

Готовые данные и код для практических кейсов офлайн AI-хакатона.

Цель репозитория — дать участникам **реальный материал**, на котором можно сразу попробовать AI-агента (Codex), не придумывая собственные данные и не настраивая базы данных.

## Шаг 0. Настройка окружения

Перед кейсами прогоните **первым делом** setup-промпт под свою ОС: [`SETUP.md`](SETUP.md). Агент сам поставит Git, Python, ripgrep, GitHub CLI и нужные пакеты, чтобы у всех было одинаковое окружение.

## Как получить локально

```bash
git clone https://github.com/MakenYutvi/hackathon-samples.git
cd hackathon-samples
```

Дальше открываете эту папку в Codex и идёте по кейсам.

## Кейсы

| Кейс | Папка | Что делаем | Для кого |
|---|---|---|---|
| A. Объяснить незнакомый репозиторий | [`cases/A-explain-repo/`](cases/A-explain-repo/) | Агент читает чужой код и объясняет: что за продукт, модули, схема, риски. | Демо ведущего; всем полезно увидеть |
| B. Данные → отчёт | [`cases/B-data-report/`](cases/B-data-report/) | Агент анализирует CSV, считает метрики, находит аномалии, делает отчёт. | Продакты + HR |
| C. Транскрипт встречи → структура | [`cases/C-meeting-transcript/`](cases/C-meeting-transcript/) | Агент превращает сырой транскрипт в summary, решения, action items. | Продакты + HR |
| D. Идея фичи → постановка + прототип | [`cases/D-feature-prototype/`](cases/D-feature-prototype/) | Агент делает мини-PRD и кликабельный чёрно-белый UI-прототип в браузере. | Продакты + HR |

В каждом кейсе есть две версии данных — **product** и **hr**. Берите свою «родную», а чужую разберите в паре с соседом или дома, чтобы погрузиться в чужой контекст.

## Все промпты в одном месте

См. [`PROMPTS.md`](PROMPTS.md) — готовые к копированию промпты под каждый кейс.

## Важно про данные

Все данные в этом репозитории **синтетические**. Любые имена, компании, цифры и диалоги вымышлены и нужны только для тренировки. Реальные личные и рабочие данные кладите в свой приватный `lastname-kb`, а не сюда.
